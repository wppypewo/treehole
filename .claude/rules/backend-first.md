# 後端先行規則

來源：`KnowledgeBase/ClaudeCode/templates/anti-ai-website-prompts.md` — Prompt B

## 工作方式（違反即失敗）

1. 在我明確說「需求確認完畢，開始實作」之前，禁止寫任何 production code。
2. 每個階段開始時，一次丟出該階段的完整問題清單，我一次回答。不要一題一題問，不要在我回答前先猜或先寫 code。
3. 確認後，分階段交付，禁止一次把整個專案丟出來。每個階段做完等我確認再進下一階段。
4. 已確認的決定後續一字不動地保留，不要自行更改。
5. 任何你不確定的事實（套件版本、API 行為），不要憑記憶猜，先問我或明確標註「需查證」。

## 階段 1：後端先行（與視覺無關，先立資料契約）

- 先設計資料庫 schema，講清楚每張表、欄位、關聯，並說明為什麼這樣設計
- 定義 API 介面（endpoint、輸入輸出），這是前端之後要接的契約
- 若這個網站有核心計算邏輯，實作它，並附上你怎麼驗證它算對的方式
- 此階段完成、我確認後，契約即凍結；之後若前端需求迫使契約變更，先提出變更提案經我核可，禁止默默改

**若後端已在先前 session 完成**：本階段改為契約 review——讀取既有 schema 與 API 定義，向我複述你理解的契約（實體、端點、輸入輸出），經我確認一致後直接進階段 2，禁止重新設計。

## 後端架構與安全禁令（硬性規定）

禁止：
- 把安全當事後補丁。認證、授權、輸入驗證從一開始就要在
- 信任任何來自 client 的資料（header、參數、body）而不驗證
- 把密鑰、API key、連線字串寫死在 code 裡或推進 repo
- 產出「能跑的 demo」但沒有人設計過的糾纏架構——每個模組的邊界與職責要說得清楚
- SQL 直接字串拼接（用參數化查詢 / ORM）
- 對外暴露的 endpoint 沒有授權檢查就能存取使用者資料
- 把金額/數值相關的核心計算只放前端而後端不驗——這類邏輯後端要是唯一真實來源
- 沉默吞掉錯誤；錯誤要可追蹤

改為：先有清楚的資料契約與模組邊界，再填實作；安全內建在每一層；金額/計算以後端為準。
