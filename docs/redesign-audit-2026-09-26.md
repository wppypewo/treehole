# 改版前審查（2026-09-26）

依據：逐檔讀 `main`（`9d34b7a`）的 `src/app/**` 與 `src/components/**`，
以及 Codex 版 `77631a6` 的 `globals.css`／`layout.tsx`／`page.tsx`。
**尚未截圖**：`.env` 缺 `DATABASE_URL`／`OWNER_PASSCODE`／`OWNER_SECRET`，全站鎖著。
下列問題全部來自程式碼，版面實際觀感要等解鎖後截圖補。

## 一、Codex 版為什麼不能當基底

它把 AGENTS.md 裡「已鎖定、不得單方面推翻」的四項改掉了，沒有留下理由：

| 鎖 | `main` | Codex `77631a6` |
|---|---|---|
| 形狀 | `* { border-radius: 0 }` | `2px` |
| 強調色 | 簾幕紅 `#c8503f` | 琥珀 `#e6aa62` |
| 標題字體 | Bodoni Moda + Noto Serif TC | Barlow Condensed + Noto Sans TC |
| 首頁一次推一部 | `FeatureFilm` | 拿掉，改成多條橫列 |

另外加了 `body::after` 雜訊顆粒、放射狀琥珀光暈、`.projection-haze`、`.screen-frame` 發光陰影、
`.poster-glow`。`design-guardrails.md` 與 `frontend-implementation.md` 都明文禁止整頁套裝飾特效。

## 二、`main` 的問題

`main` 的細節處理很紮實：無障礙、錯誤不說謊、CSP、觸控區都有顧到。問題出在結構和節奏。

### 全站

1. **每一區都是同一個節奏。** 首頁四區、詳情頁四區、人物頁作品區，全是
   「`t-section` 襯線標題靠左＋『查看全部』靠右＋內容」。首頁用 `space-y-20 sm:space-y-24`
   等距堆疊。這違反 `design-guardrails.md` 第三、四節的「每個 section 同一節奏」和「垂直間距都一樣」。
2. **全站只有一種 hover。** `MovieCard`、`LibraryGrid`、`LibraryPicks`、`UpcomingCard`
   都用同一個 `inset-2` hairline 片夾框。`animation.md` 禁止「全站只有一種通用 hover」。
3. **這是一個人用的私人片庫，但首頁看起來是公開的 TMDB 瀏覽站。**
   首頁五路資料裡只有「為你推薦」跟片庫有關；想看清單、最近評分都沒有出現在首頁。
4. **載入骨架對不上刊頭。** `loading.tsx` 畫了 eyebrow＋標題＋副標三條，
   但 `PageHeader` 已經拿掉 eyebrow 和副標，資料到位時會跳一次版。
5. **文案語氣兩套混用。** 系統腔的「暫無簡介。」「目前沒有資料。」「暫無相關推薦。」
   和文藝腔的「看到喜歡的，就留在這裡。」「清單還空著。挑幾部，排進來。」並存。
   狀態文字帶 `✓` 字元（「已收藏 ✓」「已儲存 ✓」）。

### 首頁

6. **「今晚這部」其實是熱門榜第一名**（第一部有劇照的熱門片），跟使用者無關。
   眉標在宣稱一個沒有發生的策展。
7. 開場文字塊是片名＋年份＋兩行簡介＋「查看詳情」，是通用 hero 公式，
   換成任何電影網站都一樣。這過不了最高裁決規則。

### 詳情頁

8. **「你留下的痕跡」被拆成兩區。** 收藏／想看／已看過在簡介底下，
   評分與短評在另一個 section。它們是同一件事。
9. **評分刻度在手機會斷行。** 10 格 × 44px ＋ 間距約 449px，375px 手機扣掉 40px 內距只剩 335px，
   會斷成 7＋3 兩排。
10. **狀態可以互相矛盾。** 同一部片可以同時是「想看」和「已看過」。
    要不要在標記看過時自動移出想看，涉及資料行為，列為待決定，不自行改。
11. 「返回」固定連到 `/`，從搜尋或片庫進來也會被丟回首頁。人物頁同樣。
12. 劇照首屏下面又放一張海報，同一部片的影像連續出現兩次。

### 片庫三頁

13. **三頁是同一個元件換標題。** `favorites`／`watchlist`／`watched` 的 page.tsx 只差 kind 與字串。
    已看過頁不顯示自己的評分和短評（資料在 `ratings` 表裡）；想看頁沒有「看完了」的捷徑。
14. 篩選用的是 TMDB 評分（`vote_average`），不是自己的評分。在私人片庫裡，自己的分數才是重點。
15. 「拿掉」是 11px 的淡色字。

### 瀏覽與搜尋

16. 瀏覽頁的條件是四個原生 `<select>` 排在黏性條上，底下再用一句話重述一次剛選的條件。
    類型有 19 個選項（`src/lib/genres.ts`），藏在下拉選單裡看不到有哪些。
17. 搜尋頁本身沒有大問題。它是目前結構最清楚的一頁。

### 人物頁

18. 參演作品照 TMDB 回傳順序全部倒出來，沒有依年份分組，也沒有區分主演和客串。

## 三、改版要解的事（依上面整理）

- 首頁從「TMDB 片單」改成「我的放映室」：片庫內容上首頁，開場推薦要有真實依據。
- 各區依內容給不同結構，拉開疏密。
- 每種卡片依角色給不同 hover。
- 詳情頁把「我的紀錄」收成一塊。
- 片庫三頁依用途分化：想看是待看清單、已看過是觀影日誌、收藏是精選牆。
- 文案統一成平實、資訊優先，拿掉 `✓` 字元與「暫無」句型。

## 四、資料面的前提（不改 schema）

`watched.watched_at` 與 `ratings.rated_at` 兩個時間欄位已經存在，只是 `SavedMovie` 型別沒有帶出來，
`listWatched()` 也沒有 join `ratings`。觀影日誌要的「哪天看的、給幾分、寫了什麼」全部讀得到，
**不用改 schema，但要新增讀取函式**。依 `backend-first.md`，這屬於資料契約變更，
實作到片庫階段時先提變更提案，經使用者核可再動。

### 對照時發現並已修正的問題

1. **`t-*` 字級 class 蓋掉顏色 class。** `.t-meta`／`.t-label` 等原本寫在 layer 外面，
   優先權高過 Tailwind utilities，所以「`t-meta text-paper-faint`」這種寫法的顏色一直沒生效。
   移進 `@layer components` 後，全站 16 處同時寫了兩者的地方，顏色 class 才開始生效
   （例如 `Filmography.tsx`、`SectionHead.tsx`、`StatusNotice.tsx`）。
   這些是作者原本的意圖，三方截圖都是修正後拍的；但顏色確實有變，合併前對真資料再看一次。
2. **資料庫連不上時詳情頁整頁掉進 `error.tsx`。** TMDB 正常、只有片庫讀不到時，
   現在片名、劇照、簡介照常顯示，「我的紀錄」改成一句說明加重試鍵
   （字典 `movie.ledgerUnavailable`），錯誤記在伺服器 `[movie-record]`。
3. **日文、韓文原文片名被瀏覽器硬推斜。** 原文片名用 Bodoni 斜體，但 CJK 與韓文字型沒有斜體字面，
   瀏覽器會合成一個傾斜版（實測七人の侍、기생충）。新增 `.t-original`，加 `font-synthesis-style: none`，
   西文維持真斜體，其他文字保持正體。四處原文片名（詳情頁、今晚、想看表、首頁放映表）都改用它。
4. **職務「Screenstory」沒有中文。** TMDB 的職務名，字典沒有收，畫面上直接出現英文。補為「電影故事」。
5. **`paper-faint` 壓在 `--ink-raised` 上不過 AA。** 對 `--ink` 是 4.63:1，對 `--ink-raised` 只剩 4.45:1。
   受影響的是 `ink-raised` 框裡的小字：沒有海報時的替代片名（`MovieCard`、`FavoritesWall`、`LibraryPicks`）
   與評分備註框的 placeholder，全部改用 `paper-dim`（7.39:1），規則寫進 `globals.css` 的色票註解。
   掃描用 computed style 疊合背景色逐元素算，首頁、看過、人物、詳情、搜尋五頁實測 0 項不及格。

### 已知限制

- **角色名無法翻譯。** TMDB 的 `character` 欄位不隨 `language` 參數變（zh-TW、en-US、ja-JP 實測都一樣）。
  `characterText()` 只把「(voice)」「(uncredited)」「Self」這類固定標記轉成中文，角色本名維持原文。
  這是資料來源的狀況，程式端沒有可以再做的事；自己維護一份角色名對照表不划算，不做。
- **`global-error.tsx` 沒有在執行期觸發過。** 根 layout 的資料庫讀取有 catch，外部弄不壞它，
  要觸發只能暫改原始碼。改用 `react-dom/server` 直接渲染（`src/__tests__/error-boundaries.test.ts`）：
  確認它自己帶 `<html lang>`、字體變數、深色底、`<title>`、有無 `digest` 兩種文案與重試鍵，也確認不畫導覽列；
  `error.tsx` 則確認不自己畫 `<html>`。這證明畫面本身沒問題，沒證明 Next 在正式環境一定會走到它。
- **真實資料還沒看過。** 全部檢查都在 mock 資料上。mock 另外加了兩個邊界開關實測：
  片庫全部沒有海報（替代片名顏色 `rgb(165,161,154)`，即 `paper-dim`）、片名後面再接 24 個字，
  首頁、想看、看過、收藏在 375 寬下都沒有橫向捲動，長片名正常換行。
  看過紀錄的小縮圖沒有海報時是一格空的 `ink-raised`，44px 寬放不下字，保留作對齊。
  真實片庫的筆數與內容仍要解鎖後才看得到。
